# 演示说明

这一遍演示主要看五件事：数据有没有按周期更新，记录有没有落库，断线时有没有误用旧值，报警有没有重复产生，历史记录能不能导出。

## 正常采集

启动后保持“模拟数据采集”和“正常运行”。等待十几秒，温度、压力和电流会小幅变化，趋势开始出现，数据库记录数持续增加。

最新记录里有采集时间、质量和来源。这里的 `Good` 表示本次采集成功，数据仍是模拟值。

## 高压与恢复

选择“排气高压故障”，等下一次采集。排气压力升到约 2.1 MPa，超过默认的 1.8 MPa 阈值。

打开报警页，查看发生时间。再等几秒，应该仍是同一条活动事件。确认后会新增确认时间，活动状态不变。切回正常运行，压力降下来，事件才会显示已恢复。

如果接着再次选择高压故障，程序会生成新事件，保留上一次的记录。

## 通信中断

选择“通信中断故障”，查看监控页：质量为 `Bad`，模拟量为空，压缩机和风机状态为未知，趋势停止连接新点。

如果中断前还有高压报警，断线后它会继续保留。没有读到新数据，不能判断压力已经恢复。

切回正常运行后，再到历史页筛选 `Bad`，就能找到中断期间的采集记录和错误说明。

## TCP 采集

1. 保持正常运行，点击“启动 TCP 模拟器”。
2. 把数据来源切到“本机 Modbus TCP”。
3. 查看记录来源和延迟，确认开始通过 TCP 读取寄存器。
4. 停止模拟器，观察连接失败和通信报警。
5. 重新启动模拟器，观察有效采集与报警恢复。

模拟器与采集客户端都在本机，使用功能码 03。这个步骤验证协议读取和解码，采集值仍由模拟器生成。

## 入库和导出

到历史页选择当天范围，先查全部质量，再查 `Bad`。导出 CSV 后检查来源、质量、空值和错误说明是否一致。导出的时间是 UTC，界面显示的是本地时间。

也可以用 SQLite 工具执行：

```sql
SELECT id, timestamp_utc, source, quality, temperature_c, discharge_mpa, error
FROM samples ORDER BY id DESC LIMIT 20;

SELECT name, raised_utc, cleared_utc, acknowledged_utc
FROM alarms ORDER BY id DESC;
```

点击暂停，等待几秒，记录数应保持不变。重新开始后继续增长；正常退出再打开，之前的历史记录仍在。

## 讲清楚这部分实现

可以顺着数据走一遍：后台轮询读取寄存器，解码并换算单位，标记本次质量，判断报警变化，然后把采集记录和报警写进同一个 SQLite 事务。事务完成后，界面线程更新数值和曲线。

现场接入需要另外核对点表和设备条件。本项目当前做到了本机模拟通信、数据展示和运行记录。
